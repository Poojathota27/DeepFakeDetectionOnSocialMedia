Deepfake Detection on Social Media
Overview
This project classifies social-media tweets as human-written (normal) or
bot-generated (fake) using text preprocessing and
machine-learning/deep-learning models. It includes a Django web
interface for viewing the dataset, comparing models, and predicting the
class of a tweet.
Dataset
The application uses the TweepFake dataset in Dataset/Tweepfake.csv.
The code reads it with a semicolon (;) separator and uses the tweet
text and account.type label. Dataset/test_tweets.txt contains sample
tweets for testing.

Check the dataset's original licence and terms before redistributing it.
If you cannot redistribute it, remove the CSV from the public repository
and provide a link/instructions for obtaining it.
Models and workflow
The code preprocesses tweet text by removing punctuation, stopwords, and
non-alphabetic tokens, then applies stemming and lemmatization. The
implementation uses TF-IDF features and evaluates: - Naive Bayes -
Logistic Regression - Decision Tree - Random Forest - Gradient
Boosting - CNN - Hybrid CNN + Random Forest using features extracted
from the CNN

Although the project title references FastText embeddings, the provided
views.py implementation uses TfidfVectorizer; describe this
repository's implementation accordingly.
Main files
- manage.py --- Django command-line entry point
- Deep/ --- Django project configuration and URL routing
- DeepApp/ --- views, routes, templates, and static assets
- Dataset/ --- dataset and sample tweets
- model/ --- saved model weights and TF-IDF vectorizer
- requirements.txt --- Python dependencies
Running the application
The original project instructions target an older
Python/Django/TensorFlow environment. These pinned versions may not
install together on modern Python versions. Use a compatible environment
and verify dependencies before running.

On Windows, the original project provides run.bat and
download_nltk.bat. Review the commands before running them. The Django
server is expected to be opened locally at http://127.0.0.1:8000/; the
original documentation also mentions /index.html.

For a manual setup: 1. Install a Python version compatible with the
pinned dependencies. 2. Install packages from requirements.txt after
converting it to standard requirements format if needed. 3. Download the
required NLTK resources. 4. Ensure the dataset and saved files are in
the expected Dataset/ and model/ directories. 5. Run
python manage.py runserver from the folder containing manage.py.
Repository hygiene
Do not commit __pycache__/, .pyc files, db.sqlite3, temporary
files, or generated feature arrays such as model/X.npy if they exceed
GitHub's file-size limit. The feature arrays can be regenerated by the
application from the dataset. Keep only the model artifacts needed for
inference.
Limitations
This is an educational prototype. Its predictions should not be treated
as definitive proof that a tweet is fake or bot-generated. Model
performance should be re-evaluated with a reproducible train/test split
before making claims about accuracy.
